Classés du plus grave au moins grave. Gravité évaluée pour un vrai service de vérification d'identité (KYC).

DEF-01CRITIQUE

Une pièce refusée peut être validée en la renvoyant

Constat
Une session REJECTED accepte un nouvel envoi et passe à VERIFIED. La décision finale est écrasée.
Attendu
Une décision finale est définitive : nouvel envoi refusé (erreur 409) ou statut inchangé.
Risque
Contournement de la vérification : un fraudeur réessaie jusqu'à être accepté.
Test
test_rejected_session_cannot_be_overturned_by_resubmission
DEF-02ÉLEVÉE

Un envoi sans aucune pièce est accepté

Constat
Un POST /api/sessions/{id}/document sans fichier renvoie VERIFIED.
Attendu
Erreur 400 (pièce manquante), session toujours PENDING.
Test
test_submission_without_document_is_not_verified
DEF-03ÉLEVÉE

Le bouton d'envoi fonctionne sans pièce sélectionnée

Constat
Sur la page d'envoi, « Submit capture » sans fichier envoie le texte undefined, et la session devient VERIFIED.
Attendu
Bouton désactivé ou message d'erreur tant qu'aucune pièce n'est capturée.
Test
test_submit_without_capture_does_not_verify

Autres observations

  • La décision dépend uniquement du nom du fichier (présence de « invalid »). La même image de carte spécimen est acceptée sous le nom specimen_cni_recto.jpg et refusée sous le nom cni_invalid.jpg. Normal pour un mock, mais à signaler contre un vrai service.
  • Les identifiants de session font 12 caractères hexadécimaux (48 bits). Ils servent aussi de lien d'accès à la page de capture : en production, il faudrait un jeton plus long et une expiration.
  • Point positif : l'identifiant affiché dans la page est correctement échappé. Une tentative d'injection HTML via l'URL n'a aucun effet.
